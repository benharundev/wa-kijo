## Roles

Three default roles, in descending order of privilege:

| Role | Numeric weight | Typical user |
|---|---|---|
| `owner` | 30 | Org founder; can do anything |
| `admin` | 20 | Trusted operator; manages members and most config |
| `member` | 10 | Day-to-day user; can read and create core entities |

Roles are inherited up the org hierarchy — see
[Concepts → Multi-tenancy](/concepts/multi-tenancy#role-inheritance).

## Server enforcement

Apply permissions on every controller method:

```ts
@Post()
@RequirePermission('contact:create')
create(@CurrentUser() ctx: RequestContext, @Body() dto: CreateContactDto) { ... }
```

Routes without `@RequirePermission` are **open to any authenticated
user** — deliberate, so every permission decision is explicit.

## Frontend UX

```tsx
const can = useCan();
if (can('billing:manage')) { ... }

<Can do="member:invite">
  <InviteButton />
</Can>
```

Both helpers read the same `PERMISSIONS` map at runtime, so the UX
hint and the server check can never drift.
