wa'kijo validates the entire environment via Zod
([`packages/shared/src/env.schema.ts`](https://github.com/wakijo/wa-kijo/blob/main/packages/shared/src/env.schema.ts))
at process startup. **A missing required variable fails fast** —
better than discovering it on the first user request.

The full template lives in [`.env.example`](https://github.com/wakijo/wa-kijo/blob/main/.env.example).
Copy to `.env` for local dev. In production, use your platform's
secret manager.

## What happens if a required variable is missing

```
[error]  EnvService — Failed to validate environment:
  ✖ DATABASE_URL — Required
  ✖ BETTER_AUTH_SECRET — Required
Process exiting with code 1.
```

The Zod schema runs as the first thing in `main.ts`, before NestJS
binds the HTTP port. A misconfigured deploy never starts serving — it
fails the healthcheck and orchestrators (ECS, Railway, Compose) keep
the previous container running.

## Adding a new env var

<Steps>
  <Step title="Declare in Zod schema">
    `packages/shared/src/env.schema.ts`:
    ```ts
    export const EnvSchema = z.object({
      // ... existing entries ...
      MY_NEW_VAR: z.string().min(1),  // required
      // or:
      MY_OPTIONAL: z.string().optional(),
      // or with default:
      MY_TIMEOUT_MS: z.coerce.number().int().min(1).default(5000),
    });
    ```
  </Step>
  <Step title="Add to .env.example">
    Always with a comment explaining its purpose.
  </Step>
  <Step title="Read via EnvService (never process.env directly)">
    ```ts
    constructor(private env: EnvService) {}
    // ...
    const timeout = this.env.get('MY_TIMEOUT_MS');
    ```
  </Step>
  <Step title="Document in this page">
    Add a row to the relevant table above.
  </Step>
</Steps>

Reading `process.env` directly bypasses validation and is forbidden by
the linter (Phase 5+).
