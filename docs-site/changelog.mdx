## 0.6.1 — 2026-05-17

> **Single-tier positioning.** The Community-vs-Pro framing and five-tier (A–E) matrix introduced briefly in v0.6.0 are removed. wa'kijo is a single open-source product under Apache 2.0 going forward.

### Changed

- README, NOTICE, CONTRIBUTING, SUPPORT, issue templates, PRD §8, and the docs site all stripped of "Pro / Community" comparisons and `wa-kijo-pro` references.
- Permission catalogue trimmed of orphan keys (`module:*`, `tournament:*`, `example:*`) left over from deleted modules. Added `admin:queues` to match the docs.
- Code comments in the billing module no longer reference a paid tier as the destination for additional providers.

[Full engineering CHANGELOG entry](https://github.com/benharundev/wa-kijo/blob/main/CHANGELOG.md#061---2026-05-17--drop-commercial-tier-positioning)

## 0.6.0 — 2026-05-17 — **First public release** 🎉

> **Major repositioning + first public release.** The platform-pivot direction set in earlier ADRs is **reversed** per ADR-0011 — wa'kijo is the enterprise foundation under a single business module (wa'lawe ships as its own separate OSS repo), not a multi-module platform.

### Added

- **Apache 2.0 license** ([`LICENSE`](https://github.com/benharundev/wa-kijo/blob/main/LICENSE)).
- **ADR-0011** — formalises the platform-thesis reversal. Module Registry, Customization Layer, and kernel governance dropped from v1.0. Pragmatic DDD softened to recommended pattern. Booking Core moves from a separate workspace package to an in-API module. Engines-first build order across Phases 6/8/9 before wa'lawe in Phase 10.
- **Five-epoch roadmap** — Phases 6–10 reorganised into Platform Hardening, Compliance & DX, Commerce & White-Label, Engines Build-out, and wa'lawe + v1.0 GA. v1.0 estimate ~15–22 months.
- **Stripe billing UI** — `/orgs/[orgId]/billing` upgraded from a stub to a working flow: plan list, monthly / yearly toggle, Stripe Checkout redirect, Customer Portal access, status-aware return-URL toasts, current-subscription view.

### Changed

- **Phase 6 critical path** is now Audit engine hardening + Storage engine + enterprise identity (MFA / SSO / SCIM / sessions / impersonation / IP allowlist / org lifecycle / maintenance mode).
- **`BillingService`** narrowed to Stripe-only. The `BillingProvider` interface stays open so additional providers can be added later.
- Example seed plans are now generic — replace them with the plans your product needs.
- `.env.example` cleaned of paid-provider env vars; Stripe CLI setup hint added.

### Removed

- `@wa-kijo/booking-core` workspace package
- Module Registry runtime (`Module` + `TenantModule` Prisma models, manifest scanner, dependency resolver, `@RequireModule()` guard)
- `walawe` (chess tournament) module — moves to its own OSS repo
- `_template` module
- Billplz + Curlec billing provider implementations
- Plan + Subscription columns for Billplz / Curlec

### Migration notes

For developers coming from the pre-OSS state: run `pnpm db:migrate --name drop_platform_thesis_models` to drop the orphaned `module`, `tenant_module`, and Billplz / Curlec columns.

[Full engineering CHANGELOG entry](https://github.com/benharundev/wa-kijo/blob/main/CHANGELOG.md#060---2026-05-17--oss-community-release-)

## 0.5.0 — 2026-05-02

> **Phase 5 milestone — domain feature modules complete.**

### Added

- **Contacts module** — full CRUD with E.164 phone validation,
  per-tenant uniqueness, search, tagging, blocked flag.
- **Tags module** — per-organisation tag CRUD, reusable across the
  contacts surface.
- **Conversations module** — open / close / snooze state machine,
  channel-agnostic, conversation-per-contact uniqueness.
- **Messages module** — inbound + outbound, queued dispatch, status
  lifecycle (`queued → sending → delivered | failed`).
- **Bulk contact import** — CSV upload, per-row validation,
  rate-limited.
- **Audit log** — sensitive mutations recorded automatically (member
  role changes, org config updates, bulk operations).
- **Bull-Board admin UI** at `/admin/queues`, RBAC-gated.
- **Scheduled jobs** — soft-delete cleanup, audit log partition rotation.
- **CI pipeline** — typecheck + lint + unit + integration + e2e +
  coverage, on every PR.
- **Static OpenAPI snapshot** at `docs/api/openapi.yaml`, regenerable
  via `pnpm api:openapi:dump`.
- **Customer-facing Mintlify handbook** under `docs-site/`.

### Changed

- Default cursor pagination limit raised from 20 to 25.

### Security

- Cross-tenant access fuzz suite — closes the largest open risk class
  identified in the Phase 4 review.

## 0.4.0 — 2026-05-02

> **Phase 4 milestone — frontend scaffold complete.**

### Added

- **Next.js 15 frontend** scaffold under `apps/web/`:
  - Public auth pages: sign-in, sign-up, magic-link request and
    verify, password reset request and confirm.
  - Authenticated shell with sidebar, top bar, organisation switcher,
    user menu, theme toggle.
  - Dashboard, organisation settings (members, invites, billing),
    user settings (profile, sessions, notifications, danger zone).
- shadcn/ui primitives (button, input, card, dialog, dropdown,
  select, label, badge, separator, avatar, toast, tooltip).
- TanStack Query provider with auth-aware fetcher.
- Server-side session guard in `(app)/layout.tsx`.
- Better Auth client (`@/lib/auth-client`).
- Frontend RBAC hint: `useCan()` hook and `<Can do="permission">`
  component (UX only — server `@RequirePermission` remains the
  security boundary).

### Changed

- Bumped `better-auth` to `^1.6.9`.
- Lowered Postgres dev port to `5434` and Redis to `6381` to avoid
  clashes with locally-installed Postgres / Redis.

## 0.3.0 — 2026-04-25

> **Phase 3 milestone — auth and multi-tenancy complete.**

### Added

- **Better Auth ≥1.5** integration mounted via Fastify `onRequest`
  hook at `/api/auth/*`, bypassing NestJS body parsing.
- **Organisation plugin** with extended schema (`parentOrgId`,
  `orgType`) supporting a 3-level `SYSTEM → AGENCY → WORKSPACE`
  hierarchy.
- **AsyncLocalStorage `RequestContext`** populated by `AuthGuard` and
  consumed by `BaseRepository` for automatic tenant scoping.
- **`AuthGuard`** (APP_GUARD #1) — validates session, resolves context.
- **`PermissionGuard`** (APP_GUARD #2) — enforces
  `@RequirePermission`.
- **Hierarchy role inheritance** — owner of a parent AGENCY receives
  owner authority in all child WORKSPACEs (depth limit: 3).
- **Email module** using Resend for verification, magic link, and
  invitation emails.
- Decorators: `@Public()`, `@CurrentUser()`, `@RequirePermission()`.

### Security

- Per-IP rate limit of 5 requests / 15 minutes on auth endpoints.
- Session cookies set HttpOnly, SameSite=Lax, Secure in production.
