wa'kijo modular SaaS platform

One shared platform foundation for tenant-aware B2B products, with business modules registered at boot, enabled per organisation, and extended without breaking upstream upgrades.

Runtime shape NestJS 11 + Fastify API, Next.js 15 web app, Prisma/PostgreSQL, BullMQ/Redis
Platform pivot Module Registry + TenantModule enablement replaces one-product-per-fork as the default path
Latest registered modules Contacts 0.5.0 and Conversations 0.5.0, with Conversations depending on Contacts
Shared kernel @wa-kijo/booking-core provides scheduling primitives for future booking-heavy modules

Module runtime

boot to request
A

Scan manifests

ModuleScanner discovers apps/api/src/modules/*/module.manifest.ts and skips private folders.

B

Validate contracts

Zod checks slug, SemVer, dependency ranges, permissions, hooks, custom fields, UI slots, routes, and config.

C

Resolve dependency graph

Startup aborts on missing modules, incompatible versions, or dependency cycles.

D

Sync registry tables

Module rows are upserted; removed modules become retired instead of deleted.

E

Enable per tenant

/api/v1/admin/modules toggles TenantModule state for the active organisation only.

F

Serve gated routes

Controllers use @RequireModule("slug") so disabled or unknown features resolve as 404.

Customer customization and upgrade path

mergeable by design
01 Use default module

Start with upstream wa'kijo modules and generated docs as the source of truth.

02 Enable for tenant

Turn features on per organisation through TenantModule state and config JSON.

03 Configure safely

Use manifest-declared config, permissions, routes, and future custom-field definitions.

04 Extend via hooks

Add processors, policies, UI slots, and event handlers in customer-owned modules.

05 Fork only last

Direct source changes remain the fallback when a module cannot be extended cleanly.

06 Upgrade upstream

Core fixes land once across auth, tenant scoping, billing, docs, and shared kernels.
