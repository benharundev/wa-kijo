wa'kijo SaaS Core

A tenant-aware NestJS + Next.js foundation. Three-level org hierarchy with role inheritance. AsyncLocalStorage request context. BaseRepository that scopes every query to the active organisation — no exceptions.

Runtime shape NestJS 11 (Fastify) · Next.js 15 (App Router) · Prisma 5 · PostgreSQL 16 · BullMQ + Redis 7
Tenancy model Org parent-child hierarchy, three types: SYSTEM · AGENCY · WORKSPACE. Effective role walks up to depth 3.
Auth boundary Better Auth sessions, two-guard pipeline (AuthGuard → PermissionGuard), context via AsyncLocalStorage.
Billing Stripe-only in Community. BillingProvider interface stays as the extension point for other gateways.

Request lifecycle

cookie → response
A

Fastify onRequest #1

requestContextStorage.run({ requestId, userId:'', orgId:'' … }) opens the AsyncLocalStorage store. Every downstream async call inherits it via Node async_hooks.

B

Fastify onRequest #2

Requests to /api/auth/* are siphoned to Better Auth's Node handler and the Fastify lifecycle exits. All other URLs fall through to the NestJS pipeline.

C

AuthGuard (APP_GUARD #1)

Validates the session cookie, calls resolveContext() which fetches the member + org rows, then mutates the open store with userId, orgId, orgType, userRole, globalRole. @Public() routes skip this guard.

D

PermissionGuard (APP_GUARD #2)

Reads @RequirePermission('resource:action') metadata and checks hasPermission(ctx.userRole, perm) from @wa-kijo/shared. Default-deny: missing annotation means open to any authenticated user; missing permission throws 403.

E

Controller & service

Business logic reads the full context via getRequestContext() or the @CurrentUser() param decorator. Domain events emit to BullMQ; webhook handlers verify provider signatures before processing.

F

BaseRepository

Every findById, findAll, count is scoped by tenantWhere(ctx) which injects { organizationId: ctx.orgId } into the Prisma where clause. Soft-delete (deletedAt: null) is layered on by Prisma middleware.

Org hierarchy

three types
SYSTEM

Platform root

One per deployment. Holds the operator's own users, used to administer all downstream tenants.

e.g. wa'kijo HQ
AGENCY

Reseller / parent tenant

Optional layer. Holds multiple child workspaces; agency owners inherit ownership of every workspace beneath them.

e.g. Acme Agency
WORKSPACE

Operational tenant

Where the actual work happens. Owns contacts, conversations, members, billing subscription. Most users only ever see this level.

e.g. Acme Workspace

Role inheritance

depth ≤ 3

Effective role walks up

resolveEffectiveRole() looks up the member row at the active org, then walks parentOrgId upward (max 3 hops). At each level it takes highestRole(directRole, parentRole).

Owner-of-parent inheritance

A user who is owner of Acme Agency is treated as owner in every child workspace — without an explicit member row in each. The frontend useCan() mirrors this server-side check.

Depth cap is structural

The 3-level cap is enforced both in AuthService and in getOrgAncestors(). Exceeding it raises — it indicates a cyclic or corrupted hierarchy.

Tenant isolation — where it's enforced

five boundaries
01 · Cookie HttpOnly + SameSite=Lax

Better Auth session cookie cannot be read by JS, cannot be sent on cross-site top-level POSTs. Argon2id hashing for passwords.

02 · AuthGuard Session → RequestContext

No session, no context. Public routes are explicit via @Public(); everything else must validate.

03 · PermissionGuard Role + permission check

hasPermission() is the single source of truth — same function powers useCan() on the client and @RequirePermission on the server.

04 · BaseRepository Tenant-scoped queries

tenantWhere(ctx) is non-optional. Direct prisma.model.findMany() outside the repository is forbidden by convention and tested for.

05 · Cross-tenant tests Fuzz against real Postgres

test/integration/tenant-isolation/ spins up a real container and asserts org A cannot read or write org B's data, on every repository.
